* TODO marker slice order is deepest-first, not DOM order (a stage-2 paint hazard)
An inner li's marker is appended while the recursion runs; the outer li's only
after the subtree returns, so the nested text-less row yields [circle X80, disc
X40]. At distinct Xs it is visually irrelevant, but if two markers ever coincide
(a nested ul whose gutter the author zeroes, negative margins) a last-wins paint
would cover the inner marker with the outer one. Nothing consumes Row yet; when
stage 2 paints Markers, emit outer-to-inner or document the order unspecified.
src/lib/html/block.go flow (110-113).
* TODO RowMarker carries no owning-box/style reference (stage-2 marker styling)
On the text-less nested row, Row.Box is the INNER li (the row's owner), so a
future stage-2 styling a marker glyph from Row.Box would paint the OUTER disc
with the inner li's computed style (color/font) - wrong when nested items
differ. Stage 2 must derive marker style from the owning li (walk Box ancestry
or extend RowMarker), never from Row.Box. Spec pins the {Type, X} shape; this
is a design note, not a shape change. src/lib/html/block.go RowMarker.

* TODO body text-align is lost on a pure-inline body (implicit-run wrap drops container style)
LayoutBlock wraps a body with no block child in an anonymous RoleBlock whose
St is nil, so applyAlign reads no text-align: <body style="text-align:center">
over bare text centers nothing. splitRuns anonymous runs inherit alignment via
the shared style pointer; only this synthetic top-level run loses it. Fix:
seed the wrapper's St from a shared leaf box's St (2 lines), which also gives
the implicit-run branch its first real test (none of the TestBlock* cases
exercise the !hasBlockChild wrap today). src/lib/html/block.go LayoutBlock.

* TODO recursion depth is unguarded at build ingestion (hostile-mail hardening)
